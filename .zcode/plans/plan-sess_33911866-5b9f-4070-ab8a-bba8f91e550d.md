# KDFX Fixed-Point Effect Blocks — Selectable Reverb-Slot Algorithms

## Compatibility verdict (user's concern, resolved)
The Deluge engine is already Q31: `q31_t = int32_t`, `ONE_Q31 = 0x7FFFFFFF` (util/fixedpoint.h). Existing primitives reused directly: `multiply_32x32_rshift32_rounded` (Q31 multiply), `add_saturation` (overflow guard). Render buffers are native int32 — our blocks read/write the engine's format with zero conversion. No new fixed-point convention is introduced; the only float-in-the-loop model (Mutable) is the exception, not the rule.

## Goal
Four Kurzweil-KDFX-inspired blocks as new selectable algorithms in the Reverb Model menu (slot selection, same as Freeverb/Mutable). Stereo I/O, 4+ internal lines (no 4-bus I/O changes).

## New shared utilities (only what's missing)
`src/deluge/dsp/reverb/kdfx/kdfx_util.hpp`:
- `qsum64` — 64-bit accumulator for N-line matrix sums, saturating on collapse to Q31
- `q31_dither` — triangular TPDF injected at matrix feedback (limit-cycle prevention)
- Q15 sine table + linear interpolation for quadrature LFOs
- 1-pole damping `y += (x - y) >> shift` (per-loop, integer)
- 2-pole shelf biquad in Q31 DF2T for the tone shaper
All else (multiply, saturate) comes from util/fixedpoint.h & functions.h.

## The four models (`src/deluge/dsp/reverb/kdfx/`, each implementing reverb::Base)
1. **reverb.hpp — 4-Line Orthogonal FDN**: 4 prime-length delay lines (1087/1453/1789/2137 @44.1k, scaled by Room Size), input allpass diffuser, O(N) Householder matrix (sum → `>>1` → subtract), per-line 1-pole damping + Q31 decay scalar, decorrelated stereo taps. Room Size→length scale, Damping→loop LP, Width→tap crossfeed, HPF→rumble filter.
2. **delay.hpp — 4-Tap stereo delay**: dual lines, 4 taps with independent integer delays, Hadamard ±1 cross-feedback (pure shifts) with sign-inversion for ping-pong width, loop damping.
3. **chorus.hpp — multi-tap chorus/flanger**: dual delay lines, 4 cross-coupled taps, quadrature LFOs from the Q15 table; phase-cancellation-free stereo width.
4. **tone.hpp — tone shaper / soft limiter**: 0..+18 dB integer boost, polynomial saturation `y = 1.5x − 0.5x³` in Q31 (int64 intermediate; sibling of the existing wavefolder), 2-pole resonant shelves in DF2T. Runs as 100% wet character processor (reverb slot is a send).

## Wiring (variant + enum + menu)
- `dsp::Reverb::Model` gains KDFX_REVERB, KDFX_DELAY, KDFX_CHORUS, KDFX_TONE (appended — persisted per-song as int, old songs load unchanged); added to the `std::variant`.
- `gui/menu_item/reverb/model.h` options + `strings.h` l10n entries ("KDFX Reverb", "KDFX Delay", "KDFX Chorus", "KDFX Tone"); per-model param-name switches like room_size.h already does for MUTABLE.

## Param resolution (user requirement)
KDFX menu items use high-resolution Integer ranges (max 500–1000 rather than the stock ~50), mapping full value → Q31 coefficients at set-time. External MIDI not a priority; encoder stepping fine.

## Memory/CPU
Static `std::array<int32_t, N>` per model (largest ≈ 64K samples ≈ 256 KB — Mutable already uses 128 KB float). Per-sample cost comparable to Freeverb; 32-sample blocks @44.1 kHz on the A9.
